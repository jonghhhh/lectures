7-1. 바이브코딩이란

7-2. 가장 쉬운 시작 — 대화형 AI에 프롬프트 한 번

  • 준비: Claude는 설정에서 코드 실행·파일 생성 기능 켜기 / ChatGPT는 파일만 첨부하면 데이터 분석 기능이 작동 · 무료 플랜은 업로드·사용량 제한이 있어 유료 플랜 권장

한 번 프롬프트 (복사해 쓰기)

첨부한 두 파일로 '우리 동네 소아과는 몇 곳?' 데이터 기사 웹페이지를 만들어 줘.
1) 먼저 파일의 시트·열을 보여 줘. 그다음 시군구별 0~14세 인구와 소아청소년과 전문의 수를 계산해
   어린이 1만 명당 전문의 수와 전국 순위(229개 시군구, 일반구는 시로 합침)를 구해 줘.
   두 파일의 시군구 이름이 안 맞는 경우와 처리 방법을 표로 보여 줘.
2) 그 결과로 index.html 한 파일을 만들어 줘. 데이터는 파일 안에 JSON으로 넣고, D3 v7은 CDN으로.
   - 내 시군구 선택 → "○○는 어린이 1만 명당 소아과 전문의 ○명, 229곳 중 ○위" 문장
   - 229개 시군구 점그래프에서 내 동네 강조 + 비슷한 인구 규모 10곳 비교 막대
   - 전문의 0명 지역 목록, 출처·기준일·한계 표기, 모바일 대응, 한국어
3) README.md(출처·기준일·계산 방법·한계)도 만들고, 두 파일을 내려받게 해 줘.
4) 숫자는 코드로만 계산하고 지어내지 마. 마지막에 상·하위 10곳을 표로 보여 줘.
  • 팁: Claude는 완성 페이지를 대화창에서 바로 미리 보여 준다 · 병원 위치 지도는 데이터가 커져 대화형에선 빼는 게 안전

해 보면 부딪히는 대화형의 벽

  • 대화가 길어지면 앞서 정한 규칙(지표 정의·출처 표기)을 잊는다
  • 고칠 때마다 파일을 새로 받아 다시 올린다
  • 다음 분기 새 데이터가 나오면 처음부터 다시 설명
  • 파일 크기·개수 제한 · 대화창 실행 환경이 끝나면 중간 결과도 사라짐
  • AI가 자기 계산을 스스로 검산하지 않는다

7-3. 왜 결국 메모리·스킬·에이전트로 가야 하나

대화형의 벽 코딩 에이전트의 해법 데이터저널리즘에서의 의미
규칙을 잊는다 메모리(CLAUDE.md·AGENTS.md)를 매번 자동으로 읽음 지표 정의·출처 표기가 일관된다
같은 지시를 반복 스킬에 절차를 한 번 저장 → 다음 기사에도 재사용 팀의 '하우스 스타일'·검증 절차가 쌓인다
스스로 검산 안 함 서브에이전트가 따로 원자료와 대조 작성과 검증(데스크·팩트체커) 분리
파일 받기·올리기 반복 내 폴더에서 직접 만들고 Git으로 배포 수정 이력이 남는다
새 데이터 = 처음부터 스크립트 다시 실행 → 페이지 갱신 계속 갱신되는 DB, 재현 가능
  • 정리: 한 번 만들어 볼 땐 대화형, 계속 키우는 기사·시리즈는 에이전트
  • 6-3 고도화 4단계(직접 생산·계속 갱신)와 공통 기본기(재현 가능·방법론 공개)를 실제로 지키려면 → 메모리·스킬·에이전트가 필요하다

8-2. 왜 이렇게 만드나 — 데이터저널리즘 방식

  • 수집은 한 번, 페이지는 가볍게: 원자료는 내 컴퓨터에서 정리 → 결과 JSON만 GitHub에 올린다 (API 키·대용량 원본은 올리지 않음)
  • 두 데이터를 합쳐야 답이 나온다: 의료기관 × 인구 — 시군구 이름 맞추기가 핵심 취재 작업 (예: 수원시 장안구 → 수원시, 행정구역 개편)
  • 방법론 공개: README에 출처·기준일·지표 정의·한계(전문의 '근무지' 기준, 진료과목 ≠ 간판 과목)를 적는다
  • 재현 가능: 같은 원자료 + scripts/build_data.py → 같은 결과

8-4. 복사해 쓰는 프롬프트

프롬프트 1 — 메모리

이 폴더는 '우리 동네 소아과는 몇 곳?' 데이터 기사 프로젝트야. CLAUDE.md를 만들어 줘.
- 기사 질문: 시군구별 어린이(0~14세) 1만 명당 소아청소년과 전문의 수와 의료 공백 지역
- 원자료: raw/ 폴더 (심평원 전국 병의원 및 약국 현황, KOSIS 시군구 연령별 인구). raw/는 git에 올리지 않음

프롬프트 2 — 스킬·서브에이전트 (선택)

1) 'chart-style' 스킬: D3 차트 색(3색 이내, '내 동네'만 빨강), 글꼴, 툴팁, 출처·기준일 표기 규칙.
2) 'data-checker' 서브에이전트: data/*.json의 숫자를 raw/ 원자료에서 다시 계산해 대조하고,
   이름이 안 맞아 빠진 시군구·중복·0으로 나누기를 찾아 보고. 파일은 읽기만 하고 고치지 않는다.

프롬프트 3 — 데이터 정리

raw/ 파일들을 먼저 열어 어떤 시트·열이 있는지 보여 줘. 그다음 계획을 세우고 내 승인 후 scripts/build_data.py를 만들어 실행해.
- 병의원 자료에서 진료과목이 '소아청소년과'인 행의 전문의 수를 의료기관별로 모으고, 주소로 시군구를 정한다
- 인구 자료에서 시군구별 0~14세 인구를 구한다
- 단위는 229개 시군구(일반구는 시로 합침). 두 자료의 시군구 이름이 안 맞는 경우를 표로 보여 주고 처리 규칙을 정해
- 결과: data/sigungu.json(시군구, 시도, 0~14세 인구, 소아과 전문의 수, 1만 명당, 전국 순위, 소아과 기관 수)
        data/clinics.json(기관명, 종별, 주소, 위도·경도, 소아과 전문의 수)

CLAUDE.md와 data/*.json을 읽고 페이지 계획부터 보여 줘. 승인하면 만들어.
