00

왜 코딩이 논리 훈련인가

orientation

핵심 주장

  • 코드는 컴퓨터에게 보내는 논증문임
    • 전제(입력)와 규칙(코드)이 있으면 결론(출력)이 필연적으로 따라 나옴
    • 논리학의 "타당한 추론"과 구조가 동일함
  • 사람은 애매한 말을 눈치로 이해하지만, 컴퓨터는 애매함을 허용하지 않음
    • 따라서 코딩은 "애매하게 생각하던 것을 정확하게 만드는 훈련"이 됨
    • 글쓰기 훈련이 생각을 명료하게 하듯, 코딩은 추론을 명료하게 함
  • 미디어학과 학생에게 필요한 이유
    • 뉴스·광고·알고리즘은 모두 "숨은 조건문"으로 작동함 (추천 알고리즘 = 거대한 if문 덩어리)
    • 논증 오류를 탐지하는 능력 = 가짜뉴스·과장광고를 해부하는 능력
    • AI 시대의 핵심 역량은 코드 암기가 아니라 AI에게 논리적으로 명세하는 능력임

수업의 4단계 리듬

  • 예측(P?) — 코드를 실행하기 전에 결과를 종이에 적음. 연역 훈련
  • 실행(⊢) — 컴퓨터로 검증. 예측이 틀리면 "내 추론 어디가 틀렸나" 진단
  • 설명(∴) — 코드를 자연어 논증으로 번역. 언어화 훈련
  • 변형(∀) — 규칙을 바꾸거나 일반화. 새로운 상황에 적용
미디어 렌즈

유튜브 추천 화면을 떠올려 보자. "이 영상을 본 사람에게는 저 영상을 보여준다"는 규칙이 무수히 쌓인 결과다. 이번 학기가 끝나면 여러분은 그 규칙을 읽고, 의심하고, 직접 쓸 수 있는 사람이 된다.

01

변수 — 이름 붙이기의 논리

variable · 지시(reference)

개념

  • 변수 = 값에 붙이는 이름표
    • 논리학·언어학의 "지시(reference)"와 같은 기능임: 이름이 대상을 가리킴
    • =는 "같다"가 아니라 "오른쪽 값을 왼쪽 이름에 붙여라"는 명령임
  • 좋은 변수명 = 좋은 개념 정의
    • a = 15000보다 subscriber_count = 15000이 나음
    • 이름만 보고 무엇을 가리키는지 알 수 있어야 함 — 논증에서 용어 정의가 중요한 것과 동일함
논리 언어

"구독자 수를 S라 하자.
S = 15000"

수학 증명의 "~라 하자(let)"와
완전히 같은 행위임

파이썬 
subscriber_count = 15000
channel_name = "미디어연구소"
print(channel_name, subscriber_count)

변수는 다시 붙일 수 있다

  • 같은 이름에 새 값을 붙이면 이전 값은 잊혀짐
  • 순서가 의미를 결정함 — 논증에서 전제의 순서가 중요한 것과 같음
예측 과제 P? — 실행 금지

출력값을 먼저 종이에 적으시오. 근거도 한 문장으로.

views = 100
views = views + 50
views = views * 2
print(views)
해설 보기
300. 둘째 줄에서 views는 150이 되고(이전 값 100은 사라짐), 셋째 줄에서 150×2=300. 핵심: =의 오른쪽을 먼저 계산한 뒤 왼쪽 이름에 붙인다는 순서 규칙.
02

자료형 — 세계를 범주로 나누기

data type · 범주(category)

개념

  • 자료형 = 값이 속하는 범주(category)
    • 아리스토텔레스 이후 논리학의 출발은 "이것은 어떤 종류의 것인가"라는 분류였음
    • 파이썬도 모든 값을 범주로 나눠서 다룸
  • 기초 4범주
    • int 정수 — 구독자 수, 조회수: 15000
    • float 실수 — 시청률, 평점: 4.8
    • str 문자열 — 기사 제목, 댓글: "속보입니다"
    • bool 진리값 — 참/거짓: True, False ← 논리학이 코드에 들어오는 문
  • 범주가 다르면 연산의 의미가 달라짐
    • 3 + 5 → 8 (덧셈)
    • "3" + "5" → "35" (이어붙이기)
    • 같은 +라도 범주에 따라 규칙이 다름 — "범주 오류(category mistake)"가 왜 문제인지 몸으로 배우게 됨
논리 언어

범주 오류의 고전 예:
"초록색 아이디어가 맹렬히 잔다"
— 문법은 맞지만 범주가 어긋난 문장

파이썬: "3" + 5
— 문법은 맞지만 범주가 어긋난 코드 → 오류 발생

파이썬 
print(type(15000))    # <class 'int'>
print(type("속보"))   # <class 'str'>
print(type(True))     # <class 'bool'>

# 범주 변환(형변환) = 재분류
views = int("15000")
print(views + 1)      # 15001
예측 과제 P?

각 줄의 출력 또는 오류 여부를 적으시오.

print("100" + "200")
print(100 + 200)
print("100" + 200)
해설 보기
"100200" → 300 → 오류(TypeError). 셋째 줄이 오류인 이유: str과 int는 서로 다른 범주라 +의 규칙을 정할 수 없음. 컴퓨터는 범주 오류를 절대 눈감아 주지 않는다.
미디어 렌즈

설문조사 데이터에서 "나이" 칸에 "스무살"이라고 적힌 응답을 본 적이 있는가. 데이터 분석의 절반은 이런 범주 정리(형변환)다. 여론조사 기사 뒤에는 언제나 이 지루하고 중요한 작업이 숨어 있다.

03

연산자 — 판단의 문법

operator · 진리표(truth table)

비교 연산자: 명제를 만드는 기계

  • 비교 연산자는 참/거짓으로 판정 가능한 문장(명제)을 만듦
    • views > 1000 → "조회수가 1000을 넘는다"라는 명제 → True 또는 False
    • 종류: > < >= <= ==(같다) !=(다르다)
    • 주의: =는 이름 붙이기, ==는 같은지 판정 — 행위와 판단의 구분

논리 연산자: 명제를 결합하는 접속사

  • 논리학의 세 연산이 파이썬에 그대로 존재함
    • 연접(그리고) P ∧ Q → and
    • 이접(또는) P ∨ Q → or
    • 부정(아니다) ¬P → not
  • 진리표는 외우지 않고 코드로 생성함
for P in [True, False]:
    for Q in [True, False]:
        print(P, Q, P and Q, P or Q)
PQP and QP or Q
TTTT
TFFT
FTFT
FFFF

일상어 "또는"과 논리 or의 차이

  • 일상어: "짜장 또는 짬뽕" — 보통 둘 중 하나만(배타적)
  • 파이썬 or: 둘 다 참이어도 참(포괄적)
  • 이 차이를 아는 것이 약관·법조문·기사 문장을 정확히 읽는 힘이 됨
예측 과제 P? 
age = 21
is_student = True
print(age >= 19 and not is_student)
print(age >= 19 or age < 10)
해설 보기
False → True. 첫 줄: True and (not True) = True and False = False. 둘째 줄: True or False = True. or는 하나만 참이어도 참.
미디어 렌즈

"만 19세 이상이거나 보호자 동의가 있는 경우 가입 가능" — 회원가입 약관은 논리식이다. age >= 19 or parental_consent. 약관을 코드로 옮겨 보면 애매한 조항이 즉시 드러난다.

04

조건문 — 연역 추론

if · P → Q

개념

  • if P: Q는 조건문 P → Q의 실행 버전임
    • P가 참이면 Q를 실행함 — 전건긍정(modus ponens)이 그대로 코드가 됨
    • 들여쓰기(스페이스 4칸)가 "결론의 범위"를 표시함 — 논증의 구조가 눈에 보이는 형태로 강제됨
  • 세 가지 형태
    • if — 조건이 참일 때만
    • if / else — 참이면 A, 거짓이면 B (배중률: 참 아니면 거짓, 제3의 길은 없음)
    • if / elif / else — 여러 경우를 위에서부터 차례로 검사 (배타적 선택)
논리 언어

전제 1: 조회수가 10만을 넘으면(P)
    인기 영상이다(Q)
전제 2: 조회수는 15만 → P 참
결론: ∴ Q (전건긍정)

파이썬 
views = 150000
if views > 100000:
    print("인기 영상")
else:
    print("일반 영상")

elif와 독립 if — 가장 많이 틀리는 지점

  • elif는 배타적 선택: 위 조건이 참이면 아래는 검사조차 하지 않음
  • 독립된 if는 독립 명제: 각각 따로 검사함
  • 이 구분은 논리학의 "배타적 이접 vs 독립 명제" 구분과 정확히 대응함
예측 과제 P? — 이 문제로 짝과 토론 
score = 85
if score >= 90:
    print("A")
elif score >= 80:
    print("B")
if score >= 60:
    print("합격")
해설 보기
"B"와 "합격" 둘 다 출력. elif 블록은 A/B 중 하나만 고르는 배타 구조지만, 마지막 if는 독립된 새 판단. "B만 나온다"고 답했다면 두 if의 논리적 관계를 오인한 것 — 이 오인을 스스로 언어화하면 이 장의 목표 달성.

논리적 오류를 코드로 폭로하기

일상 논증 (후건긍정의 오류)

"조회수가 높으면 좋은 기사다.
이 기사는 좋은 기사다.
∴ 조회수가 높을 것이다."
P → Q, Q ⊬ P — 타당하지 않음

코드로 반례 찾기 
articles = [
  {"views": 300, "quality": "높음"},
  {"views": 90000, "quality": "높음"},
]
for a in articles:
    if a["quality"] == "높음" and a["views"] < 1000:
        print("반례:", a)

과제: 최근 본 광고·뉴스·썸네일에서 조건 추론 오류(후건긍정, 전건부정 등)를 하나 찾아 반례 코드를 작성할 것.

05

반복문 — 귀납과 일반화

for · while · induction

개념

  • 반복문 = "모든 사례에 같은 규칙을 적용한다"는 선언
    • 논리학의 보편 양화(∀x: 모든 x에 대하여)가 코드가 된 것임
    • 귀납적 사고와 연결됨: 개별 사례를 하나씩 검토해 전체 결론을 도출
  • 두 가지 형태
    • for — 정해진 집합의 원소를 하나씩: "이 기사 목록의 모든 기사에 대하여"
    • while — 조건이 참인 동안 계속: "구독자가 1만 명이 될 때까지"
논리 언어

∀x ∈ 기사목록:
x의 제목을 출력하라

"모든"이라는 말이
기계적으로 보장됨 — 사람과 달리
하나도 빠뜨리지 않음

파이썬 
titles = ["AI 규제 논쟁", "총선 여론조사", "OTT 요금 인상"]
for t in titles:
    print(t, len(t))

누적 패턴: 개별 사례에서 전체 통계로

  • 귀납 추론의 코드 버전: 사례를 하나씩 보며 증거를 누적함
  • 패턴: ① 빈 그릇 준비 → ② 반복하며 채움 → ③ 결론 도출
view_list = [1200, 85000, 430, 150000, 9800]
total = 0                      # ① 빈 그릇
for v in view_list:
    total = total + v          # ② 증거 누적
print("평균:", total / len(view_list))   # ③ 결론

while과 멈춤 조건

  • while은 멈춤 조건을 명확히 정의하지 않으면 무한히 돎
    • "언제까지?"를 정확히 말하지 못하면 컴퓨터가 즉시 그 허점을 드러냄
    • 무한 루프는 버그가 아니라 불완전한 명세의 증거임
예측 과제 P? 
subscribers = 100
weeks = 0
while subscribers < 800:
    subscribers = subscribers * 2
    weeks = weeks + 1
print(weeks, subscribers)
해설 보기
3 1600. 100→200(1주)→400(2주)→800(3주)... 잠깐, 800 < 800은 거짓이므로 멈춤? 아니다. 3주차에 800이 되는 순간 조건 검사로 돌아가 800 < 800 = False로 종료. 따라서 3 800. — 이렇게 손으로 한 단계씩 추적(trace)하는 훈련이 반복문 논리의 전부다. 정답: 3 800.
미디어 렌즈

"댓글 10만 개를 전수 분석했다"는 기사 문장의 실체가 바로 for문이다. 사람은 10만 개를 못 읽지만 반복문은 읽는다. 계산 저널리즘(computational journalism)의 출발점이 이 장이다.

06

자료구조 — 집합과 양화

list · dict · set · tuple

개념: 낱개가 아니라 묶음으로 사고하기

  • 자료구조 = 여러 값을 하나의 논리적 단위로 묶는 방법
  • 네 가지 묶음, 네 가지 논리
    • list 리스트 — 순서 있는 목록: 기사 발행 순서, 재생목록. 수정 가능
    • dict 딕셔너리 — 이름표가 달린 묶음: 한 기사의 {제목, 조회수, 날짜}. "속성-값" 구조
    • set 집합 — 중복 없는 모임: 수학의 집합 그 자체. 교집합·합집합 연산 가능
    • tuple 튜플 — 수정 불가능한 목록: 좌표, 확정된 기록
# 한 기사 = 딕셔너리(속성-값), 기사들 = 리스트(순서 있는 모음)
articles = [
    {"title": "AI 규제 논쟁", "views": 85000, "section": "IT"},
    {"title": "총선 여론조사", "views": 150000, "section": "정치"},
    {"title": "OTT 요금 인상", "views": 9800, "section": "IT"},
]
print(articles[0]["title"])        # AI 규제 논쟁
print(len(articles))               # 3

양화사: "모든"과 "어떤"을 코드로

  • 논리학의 두 양화사가 파이썬 내장 함수로 존재함
    • 보편 양화 ∀ "모든 기사가 ~이다" → all()
    • 존재 양화 ∃ "어떤 기사는 ~이다" → any()
논리 언어

∀a: a의 조회수 > 1000 인가?
∃a: a의 섹션 = "정치" 인가?

"모든"의 부정은 "모두 아님"이 아니라
"하나라도 아닌 것이 있음"
¬∀ ≡ ∃¬

파이썬 
print(all(a["views"] > 1000 for a in articles))
# False (9800짜리가 있어도 True... 인가?)
print(any(a["section"] == "정치" for a in articles))
# True
예측 과제 P?

위 duo의 첫 출력에 대한 주석은 일부러 틀리게 적어 두었다. all(a["views"] > 1000 ...)의 진짜 출력과 이유를 쓰시오.

해설 보기
True. 9800 > 1000이므로 세 기사 모두 조건을 만족. "9800은 작아 보이니 False"라고 직관적으로 답했다면, 인상(느낌)과 판정(명제)의 차이를 경험한 것 — 이 차이를 구분하는 것이 논리 훈련의 핵심.

집합 연산: 겹침과 차이를 정확히 말하기

press_A = {"AI", "총선", "부동산", "OTT"}
press_B = {"AI", "총선", "환율"}
print(press_A & press_B)   # 교집합: 둘 다 다룬 주제
print(press_A - press_B)   # 차집합: A만 다룬 주제
print(press_A | press_B)   # 합집합: 전체 의제
미디어 렌즈

두 신문이 같은 날 다룬 주제의 교집합·차집합을 구하는 것 — 이것이 의제설정(agenda-setting) 연구의 가장 원초적 형태다. 집합 연산 세 줄이 언론학 이론과 만난다.

문자열 — 미디어 텍스트 다루기

string · 텍스트 분석 입문

개념

  • 미디어학에서 데이터의 대부분은 텍스트임: 기사, 댓글, 자막, 해시태그
  • 문자열은 "글자들의 순서 있는 목록"으로 취급됨 — 리스트에서 배운 논리가 그대로 적용됨

핵심 도구 5가지

  • in — 포함 판정(명제 생성): "속보" in title → True/False
  • .split() — 문장을 단어 목록으로 분해: 분석의 첫걸음
  • .replace() — 바꾸기: 정제(cleaning)의 기본
  • .lower() / .strip() — 소문자화 / 공백 제거: 같은 것을 같게 만들기
  • .count() — 등장 횟수 세기: 빈도 분석의 시작
headline = "[단독] 속보!! AI 규제법 국회 통과…업계 '충격'"

print("속보" in headline)              # True
print(headline.count("!"))             # 2

# 낚시성 지표 만들기: [단독], 속보, 충격, 느낌표
clickbait_words = ["단독", "속보", "충격"]
score = sum(w in headline for w in clickbait_words)
print("낚시 지수:", score)             # 3
예측 과제 P? 
text = "미디어 미디어학 미디어학과"
print(text.count("미디어"))
print(len(text.split()))
해설 보기
3 → 3. count는 겹치는 부분 문자열도 각 단어 안에서 찾으므로 "미디어학", "미디어학과" 안의 "미디어"도 셈. split은 공백 기준 3개 단어. — "단어를 센다"는 말의 애매함(부분 문자열인가, 단어인가)이 코드에서는 반드시 결정돼야 함을 보여주는 예.
미디어 렌즈 · 미니 실습

오늘자 포털 헤드라인 10개를 복사해 리스트에 넣고 낚시 지수를 계산해 보자. "낚시성"이라는 인상적 개념을 판정 가능한 지표로 조작화(operationalization)하는 것 — 사회과학 방법론의 핵심을 코드 다섯 줄로 체험한다.

08

함수 — 정의와 추상화

def · definition

개념

  • 함수 = 추론 규칙에 이름을 붙여 재사용하는 것
    • def는 definition(정의)의 줄임말 — 말 그대로 개념을 정의하는 행위임
    • 논리학·수학에서 "f(x)를 ~로 정의한다"와 동일한 구조
  • 구조: 입력(전제) → 처리(추론) → return(결론)
    • 좋은 함수는 좋은 논증과 같음: 전제가 분명하고, 결론이 하나이고, 이름이 내용을 말해 줌
  • 추상화의 힘
    • 한 번 정의하면 내부를 잊고 이름만으로 사용 가능함
    • 복잡한 문제를 "정의된 부품들의 조립"으로 바꿈 — 문제 분해(decomposition)
논리 언어

정의: 임의의 헤드라인 h에 대해,
낚시지수(h) :=
  낚시 단어의 출현 개수

정의했으므로 이제 어떤 h에도
일관되게 적용 가능함

파이썬 
def clickbait_score(headline):
    words = ["단독", "속보", "충격", "경악"]
    return sum(w in headline for w in words)

print(clickbait_score("[단독] 충격 실태"))  # 2
print(clickbait_score("기준금리 동결"))      # 0

함수 합성: 논증의 연쇄

  • 함수의 출력을 다른 함수의 입력으로 — 결론이 다음 논증의 전제가 되는 연쇄 추론
def is_clickbait(headline):
    return clickbait_score(headline) >= 2   # 판정 기준: 2개 이상

headlines = ["[단독] 충격 실태", "기준금리 동결", "속보!! 경악 영상"]
filtered = [h for h in headlines if not is_clickbait(h)]
print(filtered)   # ['기준금리 동결']
설명 과제 ∴ — Parsons 문제

다음 줄들을 논리적 순서로 배열해 "합격 판정 함수"를 완성하시오. 기준은 문법이 아니라 정의 → 판정 → 사용의 논리적 선후.

  • print(passed(85))
  • def passed(score):
  •     return score >= 60
해설 보기
def → return → print. 정의하지 않은 개념은 사용할 수 없다 — 글쓰기에서 "용어를 정의하기 전에 쓰지 말라"는 원칙과 동일.

오류와 디버깅 — 반증의 기술

error · debugging · falsification

관점 전환: 오류는 실패가 아니라 정보다

  • 오류 메시지 = 컴퓨터가 보내는 가장 정직한 피드백
    • 사람은 애매한 글을 대충 칭찬하지만, 컴퓨터는 애매한 코드를 정확히 지적함
    • 오류를 읽는 능력이 곧 실력임: 마지막 줄(오류 종류)부터 읽을 것
  • 오류의 두 층위
    • 문법 오류(SyntaxError 등) — 문장이 성립하지 않음. 컴퓨터가 즉시 알려 줌
    • 논리 오류(logic error) — 문장은 성립하지만 결론이 틀림. 컴퓨터가 알려 주지 않음 ← 이것이 진짜 훈련 대상

디버깅 = 가설-연역적 방법

  • 과학철학의 반증 절차를 그대로 사용함
    • ① 관찰: 기대한 출력과 실제 출력의 차이를 정확히 기술
    • ② 가설: "만약 X가 원인이라면"
    • ③ 예측: "Y 지점에서 Z가 관찰될 것이다"
    • ④ 검증: print()로 중간값 확인 → 가설 기각 또는 채택
  • 금지 행동: 아무 데나 고쳐 보고 되면 넘어가기 — 가설 없는 수정은 훈련이 아님
진단 과제 — 논리 오류 찾기

이 코드는 오류 없이 실행되지만 결과가 틀리다. "평균 조회수 이상인 기사 수"를 세려 했다. 가설 → 예측 → 검증 순서로 원인을 진단하시오.

view_list = [1200, 85000, 430, 150000, 9800]
count = 0
for v in view_list:
    avg = sum(view_list) / len(view_list)
    if v > avg:
        count = count + 1
    print("평균 이상 기사 수:", count)
해설 보기
두 가지 문제. ① print가 반복문 안에 들여쓰기되어 5번 출력됨(결론이 전제 검토 중에 반복 발표되는 꼴). ② avg 계산이 반복문 안에 있어 낭비(결과는 같지만 매번 재계산). 들여쓰기는 장식이 아니라 논증의 범위 표시임을 보여주는 사례. 진단문 예시: "만약 print의 들여쓰기가 원인이라면 출력이 5줄일 것이다 → 실행 결과 5줄 → 가설 채택."
미디어 렌즈

팩트체크 저널리즘의 절차가 정확히 이것이다: 주장(코드) → 검증 가능한 예측 도출 → 증거 대조 → 판정. 디버깅을 배우는 것은 팩트체크의 사고 절차를 배우는 것과 같다.

파일과 모듈 — 지식의 축적

file I/O · import

파일 읽고 쓰기

  • 지금까지의 코드는 실행이 끝나면 사라짐 — 파일은 결론을 기록으로 남기는 것
  • 기본 패턴: 열기 → 읽기/쓰기 → 닫기 (with가 닫기를 자동으로 보장)
# 헤드라인 저장
with open("headlines.txt", "w", encoding="utf-8") as f:
    f.write("AI 규제 논쟁\n총선 여론조사\n")

# 다시 읽어 분석
with open("headlines.txt", "r", encoding="utf-8") as f:
    lines = f.read().split("\n")
print(len(lines))

모듈: 남이 정의해 둔 것을 가져다 쓰기

  • import = 검증된 정의들의 사전을 통째로 빌려오는 것
    • 학문이 선행 연구를 인용하며 쌓이듯, 코드는 모듈을 import하며 쌓임
    • import collections → Counter 하나로 빈도 분석이 한 줄이 됨
from collections import Counter

words = "미디어 AI 규제 AI 총선 AI 미디어".split()
print(Counter(words).most_common(2))
# [('AI', 3), ('미디어', 2)]

이 시점부터 학생은 "모든 것을 직접 만들지 않는다"는 감각을 얻어야 함. 좋은 인용이 좋은 논문을 만들듯, 좋은 import가 좋은 코드를 만듦.

AI에게 명세하기 — 프롬프트 논리

prompt problems · specification

AI 시대의 역전

  • 이제 코드는 AI가 씀 — 그렇다면 남는 인간의 역량은 무엇인가
    • 답: 요구사항을 빠짐없이, 모순 없이, 판정 가능하게 기술하는 능력
    • 이것은 코딩 능력이라기보다 논리적 글쓰기 능력임
  • 연구 결과: 학생들의 프롬프트 실패 원인 1위는 핵심 세부사항 누락
    • 누락은 곧 추론의 구멍 — "당연히 알겠지"는 컴퓨터에도 AI에도 통하지 않음

명세의 3원칙

  • 완전성 — 모든 경우가 규칙에 포함되는가 (5자 "미만"이면? 정확히 5자면?)
  • 무모순 — 규칙끼리 충돌하지 않는가 (규칙 1과 규칙 2가 동시에 적용되면?)
  • 판정 가능성 — "적절히", "잘" 같은 애매어 없이 참/거짓 판정이 가능한가
프롬프트 문제 — 프롬프트는 1회만 전송 가능

다음 규칙의 "댓글 게시 판정" 코드를 AI에게 생성시키시오.

  1. 금지어 포함 시 무조건 게시 불가
  2. 금지어 없고 5자 이상이면 게시
  3. 금지어 없고 5자 미만이면 "너무 짧음" 안내

제출물: ① 프롬프트 원문 ② 생성 코드 ③ 경계 사례 테스트 결과(정확히 5자 / 금지어+10자 / 빈 문자열) ④ 실패 시 누락 명세 진단문

채점 기준 보기
경계 사례 3종 모두 통과하는 프롬프트를 1회에 작성하면 만점. 실패했더라도 "정확히 5자의 처리를 명시하지 않았다"처럼 누락을 명제 수준에서 특정한 진단문을 쓰면 대부분의 점수를 부여. 채점의 무게중심은 결과가 아니라 진단의 논리적 정확성.
미디어 렌즈

커뮤니티 가이드라인, 방송심의규정, 플랫폼 약관 — 모두 "판정 규칙의 명세"다. 이 규칙들이 왜 늘 논란이 되는지(애매어, 규칙 충돌, 누락 사례) 이제 코드의 눈으로 분석할 수 있다.
