1부 · 배경

왜 지금, 팩트체크인가

허위정보는 더 이상 '주변부' 문제가 아님. 팩트체크 저널리즘이 독자적 실천으로 부상한 이유임.

2020~코로나19

"마늘·소금물 예방", "5G 확산설" — 황당해 보여도 방역 정책의 신뢰를 실제로 훼손했음.

2024.12비상계엄

유튜브발 부정선거 음모론이 주변부 소음에서 국가적 사건의 배경으로 — 허위정보의 주류화.

2025대선

후보 비방 딥페이크 영상 확산, 선관위 삭제 요청 급증.

특히 선거 토론회 — 후보자의 통계·정책·업적 발언은 유권자 선택에 직결됨.
신속·정확한 검증 = 민주주의의 건강성.

2부 · 동향 — 해외 모범 사례 ②

실시간 검증의 최전선

Factiverse (노르웨이)

· 스웨덴 공영방송 SVT — 하루 120시간 분량 정치 유튜브를 AI로 모니터링
· 헝가리 총선 — 헝가리어를 모르는 팀이 영상 50개, 발언 2,528건을 몇 시간에 분석
· EU 의회·미국 대선 토론 실시간 파일럿, 전사 정확도 95%

ClaimBuster (미국 텍사스대)

2016년 미국 대선 토론에서 세계 최초 실시간 적용된 학술 시스템. "검증할 문장을 자동으로 고른다"는 연구 분야(검증 가치 탐지)를 개척 — 오늘 소개할 한국어 시스템의 탐지 모델도 이 계보임.

2부 · 동향 — 원리

AI 팩트체크의 기본 구조 — 3단계

기자의 검증 과정과 똑같음. 이 3단계는 국제 표준 틀임 (Guo et al., 2022, TACL 서베이).

STEP 1주장 탐지

"이 발언, 검증할 가치가 있나?"

검증 대상 O "실업률이 5%에서 10%로 올랐다"
대상 X "제 생각엔 이 정책이 좋음" (의견)

→

STEP 2증거 수집

"관련 자료를 찾아보자"

통계 · 공식 기록 · 기존 보도 검색
= 기자의 취재

→

STEP 3진위 판정

"증거에 비춰 참인가 거짓인가"

사실 거짓 유보
= 데스크의 판단

이 분야를 키운 공개 데이터셋: LIAR (정치인 발언 1.3만 건) → FEVER (위키 기반 18만 건) → FEVEROUS (표 형태 증거까지).

2부 · 동향 — 핵심 기술

핵심 기술 두 가지 — LLM과 RAG

🧠 LLM = 똑똑하지만 기억이 멈춘 조수

ChatGPT·Gemini 같은 대규모 언어모델. 방대한 글을 학습해 문맥 이해와 추론이 가능함.

· 약점 1 — 지식 컷오프: 학습 시점 이후는 모름
· 약점 2 — 환각: 없는 사실을 그럴듯하게 지어냄. 실존하지 않는 논문을 인용하기도 — 기자에게 치명적인 습관

🔎 RAG = 조수에게 '검색 권한'을 주는 것

답하기 전에 반드시 웹을 검색하고, 찾은 자료에 근거해서만 답하게 하는 방식.

"기억으로 답하지 말고, 자료 보고 답해."

→ 팩트체크 자동화의 세계 표준 조합 (AIC CTU · RAGAR · FactAgent)

"자료 보고 답해"라고 시켜도 AI가 몰래 기억으로 답하는 문제가 남음.이를 '구조'로 막는 방법이 4부의 핵심 중 하나임 (슬라이드 21).
2부 · 동향 — 연구

세계 연구 동향 — 국제 대회가 이끄는 발전

CLEF CheckThat!
(유럽)

20개+ 언어, 매년 과제 진화. 2025~26 신설: 수치·시점 주장 검증 + 추론 품질 평가 (Struß et al., 2026). "GDP 7% 성장" 같은 숫자 주장은 별도 종목이 될 만큼 어려움.

AVeriTeC
(FEVER 워크숍)

실제 웹 증거로 실제 주장 검증. 2025년부터 "공개 모델 + GPU 1장 + 주장당 1분" 의무화 (Akhtar et al., 2025) — 싸고 재현 가능한 시스템이 표준.

준우승·공식 베이스라인 = 한국 숭실대 팀 HerO.

SemEval-2025
(기검증 주장 검색)

39개 언어 20만 건의 기검증 팩트체크 DB에서 새 주장과 같은 것을 찾기 (MultiClaim 기반). 같은 거짓말은 국경을 넘어 재활용되니, 검증도 재활용하자는 것.

흐름: 더 싸게 · 더 투명하게 · 더 실용적으로.이 세 방향이 4부 개선 방향의 배경.
3부 · 사례

한국어 팩트체크 자동화 시스템

이종혁 (2026). 한국언론학보 70권 2호 — 한국어 팩트체크 필요성 탐지 모델 및 RAG 기반 팩트체크 자동화 시스템 개발

차별점 1전 과정 자동화

기존 국내 연구(이준환, 2022; 박성민, 2022)는 주장 탐지·데이터셋 구축까지. 탐지 → 검색 → 판정을 이어 붙인 건 한국어 첫 시도.

차별점 2실제 데이터

실험실 예제가 아니라 제21대 대선 후보자 토론회 3회 전체에 적용.

차별점 3기자와 비교

성능 기준을 벤치마크 점수가 아니라 "JTBC 기자의 실제 판단과의 일치"로 설정.

탐지 모델은 Hugging Face에 공개 — 국내 팩트체크 데이터셋 대부분이 비공개인 상황에 대한 문제의식임.

3부 · 사례 — 한계

한계 — 그래서 무엇을 개선해야 하는가

논문과 후속 검토에서 확인된 개선 지점. 흩어진 지적이 아니라, 다음 장부터 6대 영역으로 체계화함.

판단 유보 43.9%

499건 중 219건에서 "모르겠다". 증거 부족? 충돌? 맥락 실패? — 유보의 '사유'가 구분되지 않음.

증거 의존성 보장 부재

LLM이 검색 자료 대신 학습 때 외운 지식으로 판정할 위험 — 학계의 시간적 정보 누수 문제. 측정된 성능이 '시스템의 능력'인지 'AI가 원래 아는 것'인지 구분 필요.

시점 정합성 부재

팩트체크의 기준은 '발화 당시'인데, 일반 검색은 '검색하는 오늘' 기준 최신 자료를 상위에 올림.

'대체로 ~' 등급의 재현 곤란

"김포-인천공항 고속전철 10여 분" — 실제 37~39분이니 문자적으로 거짓, 취지("가깝다")로는 대체로 사실. 이 경계는 편집 판단의 영역.

단일 상용 LLM 의존

Gemini 하나만 사용, 비교 실험 부재 — 재현성·비용 문제와 직결.

4부 · Ⅰ 탐지

Ⅰ. 탐지 고도화 — 무엇을 검증할 것인가

Ⅰ-1한국어 자체 검증가치 데이터셋

번역 데이터의 한계 극복. LLM 3중 추론으로 주석 비용 절감(AFaCTA) + 한국 정치 담론의 뉴스가치 요인 반영(Harcup & O'Neill, 2017). 데이터 정제만으로 소형 모델 성능이 크게 오른다는 결과도(FactFinders).

Ⅰ-2수치 주장 하위 분류기

검증 대상의 1/3 이상이 수치 주장(Hassan et al., 2017; QuanTemp). 국제 대회가 독립 과제화(CheckThat! 2025~26)할 만큼 어려움 → 전용 검증 경로로 라우팅.

Ⅰ-3주장 정규화

"아니 그게, 작년에 실업률이 확 뛰었잖아요!" → "2025년 실업률이 상승했다"로 표준화(CheckThat! 2025 Task 2). 검색 품질이 이 변환에 크게 좌우됨.

Ⅰ-4맥락 인지 탐지

단일 문장만으로는 검증 필요성 판별 어려움. 앞뒤 발언·후보 간 공방의 역학 반영(Gencheva et al., 2017; Patwari et al., 2017의 Tathya). 다자 토론에서 '누구의 발언인가'를 정확히 짚는 데 필수.

4부 · Ⅱ 증거 수집 ③·④

Ⅱ-3·4. 본문 전문 확보와 증거 자격 심사

Ⅱ-3스니펫이 아니라 본문 전문

검색 요약 2~3줄로 판정 = 제목만 보고 팩트체크. 본문 추출 도구로 기사 전문 확보(웹페이지 읽기 에이전트: ManuSearch; 다국어 증거 추출: SEEK; 도구: Scrapling · Crawl4AI).

Ⅱ-4'인용'과 '검증'의 구분

언론 보도라고 다 같은 근거가 아님.누가 한 말을 단순 전달한 기사(인용)'와 '직접 확인한 1차 데이터(검증)'를 철저히 구분해서 수집

근거가 못 되는 자료근거가 되는 자료
· 주장 전달 보도 — "○○ 의원은 ~라고 말했다" (어휘 중복으로 검색 최상위에 옴)
· 예정 보도 — "~할 예정" (계획 ≠ 실행)
· 재인용 보도 — 원 출처가 틀리면 함께 틀림		· 1차 자료 — 통계·법령·판결문·회의록·공공기관 발표
· 언론이 직접 취재·대조해 확인한 보도
· 사후 확인 보도

타 매체의 팩트체크 기사는 허용하되 유입 비율을 반드시 명기 — 그 경우 시스템이 한 일은 '사실 대조'가 아니라 '남의 결론 인용'에 가깝기 때문(투명성의 문제).

4부 · Ⅱ 증거 수집 ⑤

Ⅱ-5. 출처 신뢰도와 증거 배치

동적 신뢰도 가중

정적 화이트리스트 → 출처 권위를 점수화해 동적 가중하는 신뢰도 인지 RAG로. 출처 간 불일치를 근거로 저신뢰 출처 자동 하향.

한국 언론사 신뢰도 사전

전문 팩트체커의 매체 평가 기준(출처 인용 관행·정정 정책·소유 투명성)을 LLM으로 옮긴 방법론(Mujahid et al., 2025)을 국내 매체에 적용 → 사전 계산된 신뢰도 사전.

위치 편향 활용

증거를 프롬프트에 넣는 순서 자체가 판정에 영향(Bernardelle et al., 2026, SIGIR) → 고신뢰 증거를 앞·뒤에 재배열. 추가 비용 0의 개선.

충돌·오염 방어

신뢰도 다른 출처의 상충 증거 앞에서 AI 신뢰성이 급락(Ge et al., 2025) → 충돌 해소 규칙. 오염 검색이 성능을 역전시킴(RAGuard) → 매체 배경 저장소(Know Your Source) · 출처 권위 인식 점검(AuthorityBench).

데스크가 하는 일 그대로 — 어느 취재원을 얼마나 믿을지, 어떤 팩트를 리드에 올릴지.그 감각을 점수와 배치 규칙으로 옮기는 작업임.

Ⅲ-1. 근거 강제 인용 grounding

"네가 아는 것은 근거가 아니다" — 규칙이 아니라 구조로 막기. 데스크가 기사의 직접 인용을 원문 대조하는 원리의 기계화.

장치 1인용 의무화

판정문의 모든 사실관계에 자료 번호 부착.

"3번 자료에 따르면 공항철도 소요시간은 37분" — 번호 없는 사실관계는 쓸 수 없음.

② 3번에 정말 그 내용이 있는가 — 자동 사실 대조(MiniCheck · Ev2R)

→

장치 3실패 시 강등

하나라도 통과 못 하면 자동 판단 유보

근거 없는 판정은 세상에 못 나감.

  • 보조 장치 — 출력 순서 고정(근거 → 판정 → 신뢰도: 결론 선행 방지) / temperature 0(판정은 일관성의 영역) / 확신도 척도 병기(Ullrich et al., 2024의 Likert 방식)
  • 이 장치가 있어야 보고되는 성능이 'AI가 원래 아는 것'이 아니라 시스템의 증거 기반 검증 능력이라 주장할 수 있음 (시간적 정보 누수 방어)
4부 · Ⅲ 판정 ②·③

Ⅲ-2·3. 판정 목표 재설정 — 3분류 + 등급은 사람

왜 '대체로 ~'는 AI 목표가 아닌가

"김포-인천공항 고속전철 10여 분" — 문자적으론 거짓(37~39분), 취지("가깝다")로는 대체로 사실. 둘 다 틀리지 않았음 — 서로 다른 질문에 답했을 뿐. 후자는 편집 판단의 영역.

국제 표준도 소분류

CheckThat! 수치 과제: True / False / Conflicting. AVeriTeC: 지지 / 반박 / 증거 부족 / 상충. 등급 없는 서술형 모델도 존재 — 미국 FactCheck.org.

Ⅲ-3. 주장 구성요소 분해 판정

주장요소별 판정
"김포공항과 인천공항은
고속전철로 10여 분 거리다"		참 두 공항이 철도로 연결됨    거짓 소요시간 10여 분 (실제 37~39분)
→ '대체로 사실'인지 '거짓'인지는 기자가 요소별 판정표를 보고 결정

근거: 복잡한 주장을 예/아니오 하위 질문으로 분해(ClaimDecomp) · 하위 질문의 프로그램식 순차 실행(Pan et al., 2023). AI 1차 산출 = 참 방향 거짓 방향 유보(사유) + 요소별 판정 + 근거 서술.

4부 · Ⅲ 판정 ④·⑤

Ⅲ-4·5. 반진실 탐지와 추론 강화

Ⅲ-4반진실(half-truth) 지원

"말은 사실인데 맥락 생략으로 오도" — '우리 임기 GDP 10% 성장'이 사실이어도 타국 평균이 20%였다면?. 전용 벤치마크·프레임워크 등장(Tang et al., 2025 — PolitiFact-Hidden·TRACER).

역할 제한: AI가 취지를 '판정'하지 않고, 취지 판단에 필요한 재료(생략된 비교 기준·맥락)를 정리해 기자에게 전달.

Ⅲ-5추론 강화와 상호 검증

· 다중 추론 경로 — 여러 갈래로 따져 보고 최선의 경로로 판정 (CheckThat! 2026 공식 과제)
· 토론식 검증 — 두 AI가 '사실'과 '거짓' 입장에서 논증, 중재 AI가 판결(DebateCV). 상충 증거 상황에서 단일 모델보다 우수
· 논리 정합성 검사 — 판정문 자체를 교열보는 에이전트(LoCal, WWW 2025)

데스크 회의의 기계화 — 한 번의 직감이 아니라, 여러 번 따져 보고 서로 반박하게 한 뒤 결론 내리기.
4부 · Ⅳ 아키텍처 ①·②

Ⅳ-1·2. 기검증 주장 DB와 모델 이원화

Ⅳ-1기검증 주장 매칭 — 검증의 재활용

같은 거짓말은 재활용됨. 새 주장 → 먼저 기존 검증 DB에서 동일 주장 검색 → 있으면 기존 판정 재사용 (비용 0).

국제 표준: MultiClaim 39개 언어 20만 건 · SemEval-2025 최고 팀 단일언어 92% · LLM 매칭(Vykopal et al., 2025)

한국의 자산: SNU팩트체크 아카이브 5,000여 건 — 멈춘 플랫폼의 유산을 AI 시대에 되살리는 길.

Ⅳ-2하이브리드 모델 라우팅

명백한 판정 → 로컬 오픈모델 즉시 종결 / 복합·상충·인과 → 상용 LLM.

국산 선택지: EXAONE(LG) · HyperCLOVA X SEED(네이버) · Kanana(카카오). 정치 텍스트 특화 소형 모델의 GPT-4급 성능 사례(Political DEBATE).

국제 표준 정합: AVeriTeC 2025 공개 모델 의무화 — 그 조건에서 한국 팀 HerO가 최상위권 입증. 비용 절감 + 완전 재현 조건을 동시에.

4부 · Ⅳ 아키텍처 ③·④

Ⅳ-3·4. 멀티에이전트와 Claude 서브에이전트

Ⅳ-3멀티에이전트 재검토 — 최소 설계

국제 동향: 분해·추론·평가 에이전트(LoCal), 5-에이전트 라이프사이클(2025), 검증 이력 메모리(MERMAID, 2026).

실무 권장은 딱 2개만 추가:
① 일관성 검토 에이전트 (경량 로컬 — 비용 0)
② 유보 재심 에이전트 (유보 건만 재검색)

Ⅳ-4Claude 서브에이전트·스킬

'질문에 답하는 조수'가 아니라 '과제를 주면 알아서 조사하고 돌아오는 조수'.

· 컨텍스트 격리 — 수십 문서를 뒤져도 잡음은 자기 작업공간에, '최종 발견'만 보고 (보조 취재기자의 메모)
· 스킬 문서 — 검증 절차(시점창·증거 자격·인용 의무)를 코드가 아닌 문서로 자산화 → 기자가 읽고 고치고 타 뉴스룸에 이식
· 예산 상한 필수 (자율 = 비용 폭주 위험)

권장: 전면 전환이 아니라 하이브리드 — 대량 처리는 구조화 파이프라인, '판단 유보' 재심만 자율 에이전트."구조화 RAG vs 자율 에이전트 검색" 비교 자체가 다음 연구의 핵심 질문.

· Factiverse — "어떤 검증은 말하는 도중에" (SVT)

음성 인식(Whisper 계열 오픈소스) → 문장 분리 → 탐지 → 검증. 선결 과제: 처리 지연의 주범인 웹 검색 속도 최적화.

현실적 이원화

명백한 건 즉시(화면 하단 자막), 복잡한 건 방송 직후 심층으로 — JTBC가 사람 손으로 하던 것의 범위 확장.

4부 · Ⅴ 산출과 활용

Ⅴ. 취재 현장에서의 활용

Ⅴ-1유보 사유 = 후속 취재 가이드

'판단 유보'는 결함이 아니라 정직함 — 문제는 사유를 모를 때.

검색 실패 검색어·기간 바꿔 재시도
증거 충돌 상충 자료 존재, 우선순위 판단
원자료 필요 사진 대조·실물·데이터 집계
단독 사안 공개 자료 없음 — 기자의 영역

유보가 막다른 골목이 아니라 취재의 출발점이 됨.

Ⅴ-2기사 초안 자동 생성

판정 라벨만이 아니라 근거를 갖춘 기사 초안까지(Qraft, TACL 2026; CheckThat! 2026 공식 과제). 물론 초안 — 데스킹은 사람이.

Ⅴ-3"작업을 보여 주는" AI

팩트체커가 원하는 건 판정 대행이 아니라 과정의 투명성("Show Me the Work", CHI 2025; "자동화가 아니라 자율지원"). 주의 — 설명이 과신을 유발할 수도(Schmitt et al., 2025).

Ⅴ-4이용자 신뢰 설계

이용자는 기존 판단과 일치하는 팩트체크만 선택 수용하는 확증 편향(전하연, 2024) → 등급만이 아니라 근거·출처를 열어 보이는 방식으로 완화.

4부 · Ⅵ 평가

Ⅵ. 성능을 정직하게 재는 법

시스템이 아니라 '시스템을 평가하는 일' 자체의 개선 — 여기가 부실하면 앞의 모든 개선이 착시가 됨.

Ⅵ-1정답 누수 차단

정답 기사가 포털 미러·커뮤니티 전재로 재유통되는 한국 환경 — 도메인 차단만으로 불충분. 언론사 코드·기사 제목 지문 등 다중 차단의 프로토콜화. 한국에선 벤치마크 만들기 자체가 하나의 연구.

Ⅵ-2커버리지·정확도 분리

"검색이 사안을 물어왔는가" ≠ "판정이 맞았는가". 합치면 검색 실패와 판정 실패를 구분 못 함. 증거 검색 품질의 별도 평가 표준 존재(Ev2R — AVeriTeC 2025 공식 채택).

Ⅵ-3내부지식 오염 감사

증거 미확보 건에서의 판정 시도율·정답률을 상시 보고 — 낮아야 '증거 기반 시스템' 주장이 성립(시간적 누수 연구와 동일 문제의식). 벤치마크·비교 언론사를 복수로 넓혀 일반화 검증.

4부 · 확장

확장 영역 — 그다음의 과제들

멀티모달 검증

이미지·영상 결합 주장. 국제 벤치마크 등장(AVerImaTeC) — 역이미지 검색을 RAG에 결합한 저비용 시스템이 상위권. 선행 자원: Reddit 100만 건 Fakeddit. 딥페이크 시대의 필수 확장이나 별도 기술 스택.

원자료 대조 경로

"2년 전 총선 사진 재사용"(사진 대조) · "지자체 수의계약서에 적힌 실제 계약 금액"(실물) · "비례대표-여성의원 비율"(데이터 집계) — 텍스트 검색으로 원리상 도달 불가. 역이미지·공공데이터 집계 에이전트라는 별도 경로, 그 전까지는 "능력 밖" 정직 표시.

의도 추론

오정보(의도 없는 오류) vs 허위조작정보(기만 의도)의 구분 — 발화 맥락·반복 패턴·전략적 생략 분석. '사실'의 사회기술적 구성 논의(이정현·박소영, 2024)와 맞닿는 지점.

중립성·매체 평가

화자별 검증 선별 비율·판정 분포 상시 공개 — "왜 우리 후보만?"에 데이터로 답하기. 개별 주장을 넘어 매체 수준 사실성·편향 평가로 확장(Mujahid et al., 2025).

종합 설계도 — 25개 방향 포함

Ⅰ

탐지

자체 데이터셋 v2 + 수치 주장 하위분류 + 주장 정규화 + 맥락 인지

Ⅳ₁

기검증 주장 매칭

SNU 아카이브 등에서 동일 주장 검색 → 일치 시 기존 판정 재사용 (비용 0)

Ⅱ

증거 수집

유형별 소스 라우팅(3계층) + 시점창 + 본문 전문 + 증거 자격 심사(인용/검증) + 신뢰도 가중 재배열

Ⅲ

판정

이원 라우팅(로컬 오픈모델 → 상용 LLM) + 구성요소 분해 + 강제 인용 + 인용 검증 후처리(실패 시 유보 강등)

Ⅳ₃

재검토

일관성 검토 에이전트 + 유보 재심(Claude 서브에이전트, 예산 상한)

Ⅴ

출력 — 기자의 검토를 위한 초안

3분류 방향 + 요소별 판정 + 근거·출처 + 취지 메모 + 유보 사유 + 기사 초안

Ⅵ

전 과정을 정직한 평가 프로토콜로 안정화

도전과 가능성

⚠ 아직 어려운 것

· 원자료 대조형 주장 (사진·실물·원시 데이터)
· 취지·의도 판단의 최종 결정
· 딥페이크 등 멀티모달 허위정보
· 검색 결과 자체의 오염·편향

역설: 단독 취재의 가치는 자동화 시대에 오히려 올라감. AI가 검증 못 하는 유일한 기사가 단독 기사이므로.

✓ 그럼에도 AI가 잘하는 것

· 범위 — 56건 → 499건, 전수 검토
· 속도 — 토론 직후 1차 스캔
· 일관성 — 모든 후보 동일 기준
· 투명성 — 근거·출처·유보 사유 첨부
· 축적 — 기검증 DB, 재등장 거짓말 즉시 대응
· 이식성 — 검증 절차의 문서화·공유 (헝가리어 모르는 팀의 헝가리 총선 분석을 기억할 것)
