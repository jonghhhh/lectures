STAGE 1

딱 세 가지 개념

목표: 오늘 등장하는 도구들의 역할 파악.

① Unity — 게임을 돌리는 "무대 장치"

  • 전 세계 게임의 절반 가까이가 Unity로 제작됨
  • 3D 공간 그리기, 물리 법칙(중력·충돌) 계산, 키보드 입력 처리를 전부 대신하는 프로그램
  • 우리가 할 일 = 무대 위에 올릴 내용 정하기뿐

② Claude Code — 코드를 대신 쓰는 "AI 조수"

  • 터미널(명령어 입력창)에서 실행하는 AI
  • "공 굴리기 게임 만들어줘" → 필요한 코드 파일을 스스로 생성·수정
  • Codex 등 다른 AI 코딩 도구로 대체 가능 — 아래 도구가 "터미널 명령만 치면 어떤 AI든" 작동하는 방식이기 때문

③ unity-cli — AI와 Unity를 잇는 "리모컨"

  • 원래 AI는 코드 파일만 만들 수 있고, Unity 화면 안(버튼·씬·에러창)은 보지 못함
  • unity-cli 설치 시 AI가 Unity를 직접 조종 — 씬 생성, 실행(Play), 에러 읽기, 스크린샷으로 자가 확인
  • 과거에는 "MCP 서버"라는 복잡한 방식 사용 → 2026년 현재는 이 CLI 방식이 더 간단·안정적이라 표준화 추세
  • 설치는 명령 두 줄로 끝
나 (한국어 지시) └→ Claude Code (코드 작성·판단) └→ unity-cli (리모컨) └→ Unity (게임 실행·화면 표시)
STAGE 2

Unity 설치 — 다운로드부터 프로젝트 생성까지

목표: Unity 프로젝트가 열린 상태 만들기. 소요 20~30분(대부분 다운로드 대기).

2-1. Unity Hub 내려받기

  1. unity.com/download 접속
  2. Download Unity Hub 클릭 (Windows/Mac 자동 인식)
  3. 내려받은 파일 실행 → 전부 기본값으로 설치
  • Unity Hub = 본체가 아니라 "관리자 프로그램" · 본체(에디터)는 다음 단계에서 Hub 안에서 설치

2-2. 계정 만들고 에디터 설치

  1. Unity Hub 실행 → 우측 상단 로그인(Sign in) → 계정 없으면 Create account (구글 연동 가능)
  2. 라이선스: Personal(무료) 선택
  3. 왼쪽 메뉴 Installs → Install Editor
  4. 목록에서 Unity 6 (LTS) 선택 — LTS = 안정 버전
  5. 모듈 선택 화면에서 WebGL Build Support 체크 (실습 2·배포용) → Install
  6. 다운로드 수 GB · 10~20분 소요

2-3. 프로젝트 만들기 — 실습마다 독립 폴더로

  • 이 강의의 원칙: 실습 1·2·3을 각각 별도 프로젝트로 진행 — 오늘은 첫 번째(실습 1용)만 생성
  1. Hub 왼쪽 Projects → 우측 상단 New project
  2. 템플릿: Universal 3D 선택
  3. Project name: Lab1_RollGame (한글·공백 금지) → Create project
  4. 1~2분 뒤 Unity 에디터 창 열림
  5. 실습 2·3 시작 때도 같은 방법으로 Lab2_VRWalk, Lab3_RPSLab을 새로 생성 (해당 스테이지에서 안내)
왜 실습마다 프로젝트를 분리하나
  • 오염 방지: 실습 1의 코드·설정이 실습 2에 영향을 주는 일 원천 차단 — AI가 파일을 만들고 지우는 바이브 코딩에서는 특히 중요
  • 문제 격리: 에러가 나도 "이 실습 안"의 문제로 한정 → 원인 찾기 쉬움
  • 부담 없는 초기화: 망가지면 그 폴더만 삭제하고 다시 시작 — 다른 실습은 무사
  • 제출·배포 단순: 과제 제출이나 빌드가 프로젝트 = 결과물 1:1로 깔끔
  • 단, 예외 있음 — 구조가 같고 조건만 다른 경우(예: 같은 실험의 조건 A/B 버전, 캐릭터 성격만 바꾼 변형)는 한 프로젝트 안에서 씬 복제나 설정 파일 교체로 처리하는 편이 효율적. "다른 것"을 만들 땐 분리, "같은 것의 변형"을 만들 땐 한 폴더 — 이것이 기준
CHECKPOINT

Unity 에디터 창이 열리고, 가운데에 하늘과 바닥이 보이는 3D 화면(Scene)이 있으면 성공. 아무것도 만지지 말고 다음 스테이지로.

STAGE 3

Unity 이해 — 화면 · 작동 원리 · 에셋 · 활용 영역

목표: AI 작업 결과를 "볼 줄" 알고, Unity가 어떻게 돌아가며 세상에서 어디에 쓰이는지 파악. 제작은 AI, 이해와 확인은 사람의 몫.

3-1. 여섯 구역 지도

구역 (기본 위치)역할비유
Scene (가운데)3D 공간 편집 화면 · 신의 시점무대 뒤에서 본 세트장
Game (가운데 탭)플레이어가 실제로 볼 화면객석에서 본 무대
Hierarchy (왼쪽)무대 위 모든 물체 목록 (공·바닥·카메라·조명)출연진 명단
Inspector (오른쪽)선택한 물체의 속성 (위치·크기·색·기능)출연자 프로필
Project (아래)프로젝트의 모든 파일 (코드·이미지·씬)소품 창고
Console (아래 탭)에러·경고 메시지 표시무전기 — 문제 발생 시 알림

3-2. 각 구역을 조금 더 깊게

  • Scene vs Game — 가장 헷갈리는 한 쌍
    • Scene = 편집용. 어디든 날아다니며 볼 수 있고, 격자와 보조선(기즈모)이 보임
    • Game = Hierarchy에 있는 Main Camera가 찍는 화면. 참가자가 볼 최종 결과
    • "Scene에선 보이는데 Game에선 안 보인다" = 카메라가 그쪽을 안 보고 있다는 뜻 → AI에 "카메라 위치를 고쳐줘"
  • Hierarchy — 목록의 구조
    • 새 프로젝트 기본 구성원 = Main Camera(눈) + Directional Light(태양)
    • 항목 왼쪽 ▶를 펼치면 부모-자식 관계 표시 — 자식은 부모를 따라 움직임 (예: 캐릭터 머리 위 이름표)
    • 더블클릭하면 Scene 화면이 그 물체로 순간이동 — 물체 찾기 필수 기술
  • Inspector — "컴포넌트"라는 개념 하나만
    • 물체의 속성이 블록(컴포넌트) 단위로 쌓여 있음 — Transform(위치·회전·크기), 모양, 물리, 스크립트(코드) 등
    • 맨 위 Transform은 모든 물체가 가짐 · Position 숫자를 바꾸면 물체가 즉시 이동 — 한 번 해볼 것
    • AI가 만든 코드도 여기서 컴포넌트로 확인됨 · 체크박스 해제 = 그 기능 일시 정지
    • 이름 옆 체크박스 해제 = 물체 통째로 숨기기 (삭제 아님)
  • Project — 창고 정리법
    • 모든 파일은 Assets 폴더 아래에 존재 · AI가 만든 코드는 보통 Assets/Scripts에
    • 씬 파일(무대 배치 저장본)은 Assets/Scenes · 더블클릭으로 씬 전환
    • ⚠️ 파일 삭제·이동은 윈도우 탐색기가 아니라 이 창 안에서 — 밖에서 만지면 연결이 깨짐
  • Console — 메시지 3색 읽는 법
    • 흰색 ⓘ = 단순 알림(무시 가능) · 노란색 ⚠ = 경고(작동은 함) · 빨간색 ⛔ = 에러(작동 멈춤·해결 필요)
    • 빨간 에러 대처법은 하나 — 직접 읽으려 하지 말고 AI에 "콘솔 에러를 확인해서 고쳐줘"
    • 오른쪽 위 Clear로 지우고 다시 실행하면 "지금" 문제만 남아 보기 편함
  • 상단 툴바 — 버튼 세 묶음
    • 가운데 ▶ ⏸ ⏭ = 실행 / 일시정지 / 한 프레임씩 진행 — Play 중엔 화면에 색조가 살짝 입혀져 "지금 실행 중"임을 표시
    • 왼쪽 도구들 = 물체 이동(W)·회전(E)·크기(R) 핸들 — 선택한 물체에 화살표·고리가 생기며 마우스로 조작
    • 오른쪽 = 계정·레이어·Layout 메뉴

3-3. 필수 조작 4가지

  • ▶ Play: 실행/정지 · Play 중 변경사항은 저장 안 됨 → 수정은 반드시 정지 후에 (색조가 없어진 것 확인)
  • Scene 뷰 둘러보기: 마우스 우클릭 유지+드래그 = 시점 회전 · 그 상태에서 W/A/S/D = 이동 · 휠 = 확대/축소 · 물체 선택 후 F = 그 물체로 화면 이동
  • 물체 선택: Hierarchy 또는 Scene에서 클릭 → Inspector에 속성 표시
  • 저장: Ctrl+S (Mac은 Cmd+S) — 습관처럼 자주
화면이 이상해졌을 때 — 만능 복구 2가지
  • 창을 실수로 닫았거나 배치가 엉킴 → 우측 상단 Layout ▾ → Default 선택 = 처음 배치로 복원
  • 특정 창이 안 보임 → 상단 메뉴 Window에서 이름 찾아 클릭 (예: Window → Panels → Console)
CHECKPOINT

① Scene에서 우클릭 드래그로 시점 한 바퀴 ② Main Camera 선택 후 Inspector에서 Position 숫자 하나 바꿔 Game 화면이 변하는지 확인 ③ ▶ Play 실행·정지 ④ Layout → Default로 복원. 네 가지가 되면 화면 투어 완료.

3-4. 작동 원리 — Unity는 어떻게 돌아가나

  • 레고식 조립: 게임오브젝트 + 컴포넌트
    • Unity 세계의 모든 것 = 게임오브젝트(빈 껍데기) + 거기에 끼우는 컴포넌트(기능 블록)
    • 예: "공" = 게임오브젝트 + 구 모양 컴포넌트 + 물리 컴포넌트(Rigidbody) + 코드 컴포넌트(굴리기 스크립트)
    • 같은 껍데기에 다른 블록을 끼우면 다른 존재가 됨 — 카메라도, 조명도, AI 캐릭터도 전부 이 조립식
    • AI에게 "공에 튕기는 성질을 추가해줘"라고 하면 = 컴포넌트 하나를 더 끼우는 작업
  • 씬(Scene) = 무대 배치 저장본
    • 어떤 게임오브젝트들이 어디에 어떤 상태로 있는지 기록한 파일
    • 프로젝트 하나에 씬 여러 개 가능 — 메뉴 화면 씬, 게임 씬, 실험 조건 A/B 씬처럼 무대를 갈아끼우는 단위
  • 게임 루프 — 1초에 수십 번 다시 그리기
    • Play를 누르면 Unity는 "입력 확인 → 물리 계산 → 코드 실행 → 화면 그리기"를 1초에 30~60번 반복
    • 이 한 바퀴 = 프레임(frame) · 초당 횟수 = FPS — 게임이 "부드럽다/버벅인다"의 정체
    • 코드의 핵심 함수 이름이 Update인 이유 = 매 프레임 호출되기 때문 (AI 대화에서 자주 보게 될 단어)
  • 물리 엔진 — 세상의 법칙 담당
    • 중력·충돌·마찰·관성을 Unity가 자동 계산 — 공이 "알아서" 떨어지고 구르는 이유
    • 이 물리적 사실성이 뒤에 나올 시뮬레이션·디지털 트윈 활용의 근거 — 가상에서의 실험 결과가 현실 예측에 쓰일 수 있는 이유
  • 카메라와 렌더링 — 보이는 것의 원리
    • 3D 세계는 데이터일 뿐 · 카메라 컴포넌트가 그중 한 시점을 골라 2D 화면으로 계산해 그림 = 렌더링
    • 조명(빛의 방향·색)이 같은 물체를 완전히 다르게 보이게 함 — 분위기 연출의 핵심
  • 빌드 — 완성품 내보내기
    • 에디터에서 만든 것을 실행 파일로 포장하는 과정 · 같은 프로젝트를 Windows 앱, 웹(WebGL), 스마트폰 앱, VR 헤드셋용으로 각각 빌드 가능
    • "한 번 만들어 여러 기기로" — Unity가 산업 표준이 된 이유 중 하나

3-5. 에셋(Asset) — 재료의 세계

  • 정의: 프로젝트에 들어가는 모든 재료 파일 — Project 창의 Assets 폴더가 이름 그대로 재료 창고
  • 종류 한눈에
    • 3D 모델: 물체의 형태 (사람·나무·건물) · 표준 파일 형식 = GLB/FBX
    • 머티리얼(Material): 표면의 "페인트" — 색·광택·질감을 정하는 설정
    • 텍스처(Texture): 표면에 붙이는 이미지 (나무결, 벽돌 무늬)
    • 애니메이션: 움직임 데이터 (걷기·인사·춤)
    • 오디오: 효과음·배경음
    • 스크립트: C# 코드 — 코드도 에셋의 일종
    • 프리팹(Prefab): "붕어빵 틀" — 완성된 조립품을 틀로 저장해 복제 · 동전 5개는 동전 프리팹 하나에서 찍어낸 것
  • 어디서 구하나
    • Unity Asset Store: 에디터 안 상점 · 무료~유료 · 배경 세트, 캐릭터, 효과음까지
    • 외부 무료 소스: Ready Player Me(사람 아바타), Mixamo(동작), Sketchfab(3D 모델 — 라이선스 필터 확인)
    • AI에게 "무료 에셋을 찾아 적용해줘"라고 지시하는 것도 가능
  • 주의 2가지: ① 라이선스 확인(무료여도 출처 표기 조건이 흔함) ② 무거운 에셋은 로딩·성능 저하 — 웹 배포용은 "low poly(저용량)" 위주

3-6. 활용 영역 — 게임 엔진이 세상을 시뮬레이션하는 도구가 되기까지

  • 게임: 본업 · 전 세계 모바일 게임의 다수가 Unity 제작 — 배운 기술 그대로 취업·창작 영역

  • VR · AR · XR: 헤드셋 콘텐츠 제작의 표준 도구 · 오늘 실습 2가 그 입구
  • 시뮬레이션 · 연구
    • 물리 엔진 덕에 "가상에서 안전하게 실험" 가능 — 로봇 훈련, 자율주행 테스트, 재난 대응 훈련
    • 합성 데이터 생성: 실물 대신 가상 장면을 대량으로 찍어 AI 학습용 이미지 제작 — 보잉은 항공기 디지털 트윈으로 10만 장 이상의 합성 이미지를 만들어 검사용 AI를 학습시킴
    • 사회과학 실험: 참가자를 통제된 가상 상황에 넣고 행동을 기록 — 우리 수업의 방향
  • 디지털 트윈(Digital Twin)
    • 정의: 실제 공장·건물·도시·기계를 그대로 본뜬 가상 쌍둥이 — 센서 데이터를 실시간으로 받아 현실을 비추고, 가상에서 먼저 실험해 현실을 예측
    • 활용 산업: 제조(공장 배치 최적화·로봇 훈련), 자동차(설계 검증·생산 공정), 건설·건축(가상 검증으로 15~20% 효율 향상 사례), 에너지(설비 원격 운영), 도시계획, 헬스케어
    • 왜 게임 엔진으로? — 실시간 3D 그래픽 + 물리 시뮬레이션 + 상호작용이 이미 갖춰진 플랫폼이기 때문
    • 미디어 연구와의 접점: 여론·커뮤니케이션의 "사회적 디지털 트윈"(가상 사회 시뮬레이션)이라는 신생 영역

    • 정해진 대사만 하던 NPC에 LLM의 뇌를 연결 → 자유 대화하는 캐릭터 (오늘 실습 3)

  3. aistudio.google.com → 구글 로그인 → Get API key → 발급(무료) → 복사
API 키 = 비밀번호 — 코드에 직접 쓰지 않고 .env라는 별도 파일에 보관이 표준 · 아래 프롬프트가 그 파일을 만들게 하며, 키 값만 우리가 직접 붙여넣음 · .env는 공유·업로드 금지

7-2. 서버(심판)도 AI에게 — 프롬프트 하나로 (10분)

  • 터미널에서 cd 프로젝트경로/Lab3_RPSLab → claude 실행 후 붙여넣기:
이 프로젝트는 "가위바위보 챗봇 실험" 전용이야. 먼저 server 폴더에 파이썬 FastAPI 서버(rps_server.py)를 만들어줘. 요구사항:

1. server/.env 파일을 만들고 GEMINI_API_KEY=여기에_키_입력 형태로 비워둬라. 서버는 python-dotenv로 .env에서 이 키를 읽어 gemini-2.5-flash-lite 모델을 사용한다.
2. POST /chat 엔드포인트: 입력 JSON은 text(참가자의 말), player_hand(rock/paper/scissors, 선택), pid(참가자 번호). CORS는 모두 허용.
3. 캐릭터 설정: '단추'라는 명랑한 가위바위보 챔피언. 반말로 짧게(1~2문장) 대답하고 가끔 심리전 멘트를 던진다. 참가자가 대결을 원하거나 손을 냈으면 단추도 손을 내되, 응답에서 ai_hand 필드로 분리해 반환한다.
4. 참가자와 단추가 모두 손을 냈으면 승패를 판정해 result(win/lose/draw)로 반환한다.
5. 매 요청을 server/experiment_log.csv에 한 줄씩 기록한다 (time, pid, player_text, player_hand, ai_text, ai_hand, result).
6. 온라인에서 여러 참가자가 동시 접속할 수 있으니, 대화 기억(history)을 전역 하나가 아니라 참가자 번호(pid)별로 분리해 관리하라 — 참가자 간 대화가 절대 섞이면 안 된다. 각 pid의 첫 요청 시각(세션 시작)도 로그에 함께 기록하라.

필요한 패키지를 설치하고 서버를 8000번 포트로 실행한 뒤, 테스트 요청을 보내 대답·판정·CSV 기록이 되는지 스스로 검증하고 결과를 보여줘.
  • AI가 만든 server/.env를 열어 복사해 둔 키를 붙여넣기 → AI에게 "키 넣었어. 서버 재시작하고 다시 검증해줘"
CHECKPOINT

AI의 검증 결과에 단추의 대답과 승패 판정이 보이고, server/experiment_log.csv가 생겨 있으면 심판 완성. 서버 터미널은 켠 채로 유지.

7-3. Unity 무대도 AI에게 (10분)

  • 이어서 같은 Claude Code 창에 붙여넣기:
이제 Unity 쪽이야. unity-cli status로 연결 확인 후 "RPSLab" 씬을 만들어줘. 방금 만든 http://localhost:8000/chat 서버를 사용한다.

[무대] 밝은 방. '단추' 캐릭터(캡슐 몸 + 동그란 머리, 주황색)가 테이블 건너편에 서 있음.
[상호작용] 1. 화면 아래 채팅 입력창 — 글을 쓰면 서버로 전송, 단추의 대답을 머리 위 말풍선으로 표시. 2. 화면 오른쪽 [바위] [보] [가위] 버튼 — 누르면 player_hand로 함께 전송. 3. 단추의 ai_hand 수신 시 단추 앞에 모양 표시 — 바위=구, 보=넓은 판, 가위=교차 막대 2개. 4. result 수신 시 화면 가운데 "승리!/패배/무승부" 1.5초 표시 + 위쪽에 전적 누적. 5. 시작 화면에서 참가자 번호(pid)를 입력받아 매 요청에 포함.

[확인] Play로 한 판 직접 해보고 스크린샷을 보여줘. 연결 에러가 나면 콘솔을 읽고 스스로 고쳐라.
CHECKPOINT

채팅 "안녕! 한 판 붙자" → 단추 응답 · [바위] 클릭 → 단추도 손 제시 + 승패 표시 = 완성. experiment_log.csv 확인 — 모든 상호작용이 데이터로 기록되어 있음.

7-4. 이것이 왜 "실험"인가

  • 구조 = 사람이 AI 에이전트와 상호작용 + 모든 행동이 자동 기록
  • 캐릭터 성격(프롬프트 3번 항목 한 문단)만 바꾸면 연구 질문 성립:
    • "단추가 예의 바를 때 vs 얄미울 때 — 사람들은 어느 쪽과 더 오래 노는가?"
    • "'너 또 바위 낼 것 같은데?' 압박 멘트가 사람의 선택을 바꾸는가?"
  • 로그 CSV = 그 답을 주는 데이터 · pid별로 대화가 분리 기록되므로 참가자 단위 분석(대화량·선택 패턴·세션 길이) 가능
확장 아이디어: 푯말 들기 여론 실험
  • 가위바위보 대신, 단추와 친구 캐릭터 2명이 질문("축제 야식은 떡볶이 vs 치킨")에 O/X 푯말을 먼저 들기 → 참가자가 자기 푯말 선택
  • 관찰 포인트: 캐릭터 둘이 모두 반대편일 때 참가자는 소신 유지? 동조?
  • = 동조·침묵의 나선 이론 검증 실험의 원형 · 프롬프트의 캐릭터 설정과 버튼만 바꾸면 됨

8-3. 실습 3 온라인 배포 — Hugging Face에 서버·키·데이터 한 번에

  • 질문에 대한 답 정리:
    • GitHub Pages만으로 되나? → 화면은 됨, 서버는 안 됨 (Pages는 파일만 보여주는 "게시판" — 파이썬 실행 불가)
    • API 키는 어디에? → 브라우저에 두면 누구나 꺼내 쓸 수 있음 → Space의 Secrets(서버 쪽 금고)에 보관하면 참가자에게 절대 노출 안 됨
    • 데이터는 어디에? → Space 내부 파일은 재시작 시 사라짐 → HF Dataset 저장소에 자동 커밋(CommitScheduler)이 정석 — 영구 보존 + 이력 관리 + 비공개 설정 가능
    • 로컬 서버로도 되나? → 오프라인 실험(참가자를 실험실로 부르는 방식)이면 됨 (8-4 참조)

① 데이터 창고 만들기 — Dataset 저장소 (2분)

  1. huggingface.co 로그인 → 우측 상단 프로필 → New Dataset
  2. 이름 rps-logs · Private 선택(연구 데이터이므로) → Create
  3. 프로필 → Settings → Access Tokens → Create new token · 권한 Write → 토큰 복사해 두기

② 서버 올리기 — Space 만들기, 변환은 AI에게 (10분)

  1. 우측 상단 ＋ → New Space · 이름 rps-server · SDK는 Docker (Blank) · Free CPU → Create
  2. Claude Code에 변환을 지시:
로컬에서 돌던 server/rps_server.py를 Hugging Face Docker Space용으로 변환해줘. hf_deploy 폴더에 세 파일을 만들어라:

1. app.py — 기존 서버와 동일 기능. 단 (a) .env 대신 환경변수에서 GEMINI_API_KEY를 읽고, (b) huggingface_hub의 CommitScheduler로 logs/ 폴더를 5분마다 "내아이디/rps-logs" Dataset 저장소(repo_type=dataset)에 자동 커밋해라 (토큰은 환경변수 HF_TOKEN 사용, 기록 시 scheduler.lock으로 보호).
2. requirements.txt — 필요한 패키지 목록.
3. Dockerfile — 7860 포트로 uvicorn 실행, logs 폴더 쓰기 권한 포함.

"내아이디"는 내 허깅페이스 아이디로 물어보고 채워라. 완성 후 각 파일의 역할을 한 줄씩 설명해줘.
  1. Space 화면의 Files 탭 → Add file로 hf_deploy의 세 파일 업로드

③ 금고에 키 넣기 — Secrets (2분)

  1. Space의 Settings 탭 → Variables and secrets → New secret
  2. 추가 1: 이름 GEMINI_API_KEY · 값 = 발급받은 Gemini 키
  3. 추가 2: 이름 HF_TOKEN · 값 = ①에서 복사한 Write 토큰
  4. 저장하면 Space가 자동 재시작 · 상단 표시가 Running이 되면 가동 완료
  • 서버 주소 = https://내아이디-rps-server.hf.space · 브라우저로 접속해 {"ok":true} 확인
  • 키·토큰은 Secrets 안에만 존재 — 코드에도, 브라우저에도, 저장소에도 없음
잠들기(cold start) 관련
  • 무료 Space는 약 48시간 미사용 시 잠듦 → 깨어나는 데 수십 초 소요
  • 실험 기간 중 하루 한 명이라도 접속하면 사실상 상시 가동 · 안전장치로 실험일 아침 한 번 접속해 깨워두기
  • 수집 데이터 확인: 내 Dataset 저장소(rps-logs) 페이지에서 CSV가 5분 간격으로 갱신·버전 관리됨

④ Unity가 새 서버 주소를 보게 하고 재빌드 — AI에게 지시

RPSLab 씬의 서버 주소를 http://localhost:8000/chat 에서 https://내아이디-rps-server.hf.space/chat 으로 바꿔줘. 그리고 시작 화면에서 참가자 번호(pid)를 입력받아 매 요청에 함께 보내도록 수정해줘. 완료되면 WebGL로 빌드해줘 (Compression Format은 Disabled).

⑤ 화면을 GitHub Pages에 올리기 — 8-2의 ②③과 동일 절차 (저장소 이름만 rpslab 등으로)

CHECKPOINT

휴대폰에서 https://내아이디.github.io/rpslab/ 접속 → 참가자 번호 입력 → 단추와 대화·대결 가능, 그리고 몇 분 뒤 rps-logs Dataset에 그 기록이 나타나면 온라인 실험 배포 완성. 참가자에게 링크만 전송.

8-4. 오프라인 실험(실험실 방식)은 더 간단

  • 참가자를 실험실로 부르는 방식이면 클라우드 불필요:
    • 방법 A (가장 간단): 실험용 PC 한 대에서 서버 + Unity를 모두 실행 → 참가자가 그 자리에서 참여
    • 방법 B (여러 대): 서버 PC 한 대 + 같은 와이파이의 참가자 PC들 — 서버 PC의 내부 IP(예: 192.168.0.10:8000)를 Unity 주소로 설정하면 같은 네트워크 안에서 접속 가능
  • 정리 — 온라인 대량 모집 = GitHub Pages + 클라우드 서버 · 실험실 소수 정밀 측정 = 로컬로 충분 · 연구 설계에 따라 선택

8-5. 배포 구조 한눈에

[온라인 실험] 참가자 브라우저 ──> GitHub Pages (Unity WebGL 화면 · 실습 1·2는 여기서 끝) │ https ▼ Hugging Face Space (파이썬 서버 · Secrets에 GEMINI_API_KEY) │ │ 5분마다 자동 커밋 ▼ ▼ Gemini API HF Dataset 저장소 (실험 데이터 영구 보존) [오프라인 실험] 참가자 PC(같은 와이파이) ──> 실험실 PC (Unity + 파이썬 서버 localhost)
